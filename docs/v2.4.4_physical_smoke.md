## Reproducción física que motivó 2.4.4

Se instaló un candidato profile `2.4.4+11` en el Samsung `SM-S942U` y se
ejecutó `v2_4_4_room_completion` antes de cerrar la corrección de inventario.
La traza es diagnóstica: no hubo una retirada física controlada ni ground
truth, por lo que no certifica pickup ni habitación limpia.

| Medida | Resultado |
|---|---:|
| Duración | 109.60 s |
| Frames registrados | 438 |
| Inferencia nativa p50 / p95 | 125.89 / 139.56 ms |
| FPS nativo p50 / p05 | 4.07 / 3.35 |
| Inventario inicial observado | creció de 3 a 5 |
| Tracks missing finales | 7 |
| `toyTemporarilyMissing` | 89 |
| `toyReappeared` | 71 |
| `ToyCollected` | 0 |
| `CleanupCompleted` | 0 |

La traza confirmó el defecto reportado: durante el paneo aparecían identidades
nuevas y el inventario de la misión crecía. La implementación final congela el
inventario durante la recogida y sólo admite un objeto nuevo en la barrida
final después de 600 ms detector-confirmado en una vista estable. Esta traza
no se presenta como validación de la implementación posterior.

## Instrumentación verificada

El overlay profile mostró en vivo:

- fase y objetivo activo;
- YOLO/open-set/confirmados/candidatos;
- tracks activos, missing, recogidos y restantes;
- estabilidad, movimiento y ancla de escena;
- evidencia de retirada, duración missing, reaparición y transición;
- cobertura, tracking, ventana sin objetos, decisión y bloqueadores.

El overlay queda excluido mediante `kReleaseMode`. El modo visual efectivo
fuerza la superficie infantil cuando Kid Mode está activo, incluso si antes se
seleccionó diagnóstico; esa regresión está cubierta por prueba automatizada.
